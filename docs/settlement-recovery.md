# 日结锁冲突与近七天补偿（v1.4.2）

## 原因与修复

日结在同一事务中读取账单并写入结算单。SQLite WAL 下其他写者提交会使旧读快照无法升级为写事务，busy_timeout 不一定能恢复。仅重试最后一次写入会复用旧快照，因此必须整体回滚后重新聚合。

仅 SQLite BUSY/LOCKED 允许最多五次完整事务尝试，退避可被 context 取消。已审核差异、源数据损坏、其他数据库错误不作为瞬时锁重试。金额与退款归属沿用原口径，已审核单不覆盖，生成不触发付款。

## 补漏边界

- 启动及每小时检查服务本地自然日的昨天至前七天，从最旧账期开始。
- 成功后写入持久账期检查点；失败不标记成功，下轮仍会尝试。一个账期失败不阻塞其他账期。
- 生成成功但检查点写入失败会安全重跑，依靠原结算单唯一键与审核保护保证幂等。
- 首次部署会检查近七天尚无检查点的账期；不会自动重算七天以外的历史账。
- 成功检查点不是账本封账或付款凭证。标记成功后又到达的历史数据、迟到退款修订和七天以前的漏单，仍需管理员按原有审计流程核对。
- 同进程补偿串行执行；不宣称支持多实例强单飞。跨实例依赖原事务/唯一约束及审核保护。

## 生产核验

只读脚本检查健康状态、近七天源账单及结算单数量与金额摘要，不调用生成接口、不修改资金。发布后可设置 `REQUIRE_CHECKPOINTS=1`，缺任一账期成功检查点即以非零退出。不能仅凭健康为 ok 或账单数量相同宣称财务对账完成。
