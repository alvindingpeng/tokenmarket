# TOTP 双因素认证

## 使用

设置 → 账号 → 双因素认证。先重新确认密码，再用认证器扫描本地生成的二维码（或手工输入密钥），输入动态码确认启用。启用后保存一次性恢复码，所有旧会话会失效；重新登录需密码和新的动态码，或一枚恢复码。

动态码采用 RFC 6238、SHA-1、六位、30 秒步长，容忍前后各一步时钟漂移。已使用的时间步不能重放，绑定确认使用的码也不能立即用于登录：请等下一码或使用恢复码。手机和服务器应开启自动校时。

解绑需要登录态、密码二次确认，以及动态码或恢复码；解绑同样吊销既有会话。没有设备且没有恢复码时不会经密码找回自动绕过 2FA，请先保留恢复码。

## 安全边界

- TOTP 密钥使用部署的 KEK 信封加密，并绑定 users 的用户 ID 和字段名；主密钥不可用时拒绝设置与校验，不回退明文。
- 恢复码为随机 128 位，仅首次启用响应返回明文，数据库只存 SHA-256 摘要；浏览器仅在内存显示，不写 localStorage/sessionStorage。
- 账号维度持久限流（每五分钟最多十次 2FA 操作/校验），登录另有原有 IP+账号防爆破闸门。知道密码不能通过不断重置登录失败次数暴力猜码。
- 数据库 CAS 防止并发消费同一码、覆盖启用状态或复活已吊销会话。启用/解绑递增会话版本。
- 三个管理端点均需要现成的 step-up 重认证凭证，响应设置 no-store。审计不记录密钥、动态码或恢复码。
- 二维码使用浏览器本地 SVG 生成，无第三方二维码请求。服务器不会替用户自动启用 2FA。

## 备份与恢复

物理备份必须同时保留数据库及其匹配的部署 KEK（分开安全保管）；只保留数据库将无法解密 TOTP 密钥。现有 JSON 配置导入导出不包含用户账号，也不是用户/2FA 备份工具。启动校验会拒绝损坏、未加密、跨用户搬移的 TOTP 密文，避免悄悄跳过第二因素。
