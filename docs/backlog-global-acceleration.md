## B. G2 边缘启用(卡在外部依赖)

### B1. Cloudflare 边缘证书未签发

- **现状**: `tt.xjj.se` 的**边缘**证书缺失 —— CF 免费版不允许在边缘安装第三方证书, 只能由 CF 自己签发。`api.xjj.se` / `dsh.xjj.se` 都有各自单主机名的 LE 证书, 说明该 zone 是按主机名逐个签发的, `tt.xjj.se` 还没进覆盖范围。裸域 `xjj.se` 同样没有。
- **为什么没做**: 需要 Cloudflare 后台操作(本机无 API token)。
- **该怎么做**: SSL/TLS → Edge Certificates 把 `tt.xjj.se` 签出来 → 把云朵点回橙色 → SSL 模式设 **Full (strict)**。
  **nginx 一行都不用改** —— `real_ip` 的 CF 网段与 `CF-IPCountry` 来源校验都已就位。
- **坑**: 设成 Flexible 会因源站 80→443 的 301 出现重定向循环。
- **验收**: `curl https://tt.xjj.se/healthz` 响应头里出现 `cf-ray`, 且状态 200。

### B2. 边缘启用后要盯的两个硬限制

- 请求体 **100MB** 上限(CF 免费版), 超过在边缘就被拒; 源站的 512m 只对直连生效。生图/生视频超量会 413。
- 非流式请求 **100 秒**无字节即 524。当前 237 条带计时的请求里最大首字节 4.5s, 无风险; 长生成与视频任务要盯。

### B3. 可选的源站加固(不建议现在做)

- 443 只放行 CF 网段与内网(`allow ...; deny all;`), 禁止绕过边缘直连源站。
- **为什么不做**: CF 调整网段时会导致整站不可达, 而当前收益有限(灰云期间本来就直连)。

### B4. CF 网段是静态快照

- `/etc/nginx/conf.d/switchyard-cf-geo.conf` 里的 22 条网段取自 `cloudflare.com/ips-v4|v6`, 写死在配置里。
- **需要时**: 重新拉取两个列表并重生成该文件, 然后 `nginx -t && systemctl reload nginx`。

### B5. G2 的验收指标还没测

- 文档原定"全球 5 个探针点 TLS 建连 p95 < 300ms"与"首字节改善 ≥ 15%"。
- **为什么没测**: 灰云下没有边缘节点, 测了也不代表边缘效果; 需先完成 B1。

## C. G3 出口池: 代码就绪, 配置为零

### C1. 线上没有任何出口配置

- `channel_egresses` 表 0 行。出口池的价值完全取决于有没有真实的第二条线路(代理/专线)。
- **该怎么做**: 在渠道编辑页的「出口」步骤里配 2 条以上真实线路, 系统会自动择优并在失败时切换。
- **注意**: 配了出口就**不再使用**渠道自身的 `proxy` / `channel_proxy`; 想回退到旧行为, 把出口删空即可。

### C2. 区域亲和默认关闭, 且依赖 B1

- `egress_region_bonus_ms = 0`(关闭)。
- 该功能靠 `CF-IPCountry` 头, 而**只有开橙云后 Cloudflare 才会注入**这个头。灰云期间即使调大该值也没有数据可用 —— 先做 B1。

### C3. 出口成绩只存进程内

- 重启后重新学习(每条出口被选中一次即有样本; 一个不通的出口最多让一次请求失败)。
- **为什么这么设计**: 持久化要动 `route_metrics` 的格式, 收益不成比例。
- **触发重估的条件**: 出口数量多到"重新学习"的代价明显(例如几十条出口、且每条要很久才有样本)。

### C4. `weight` 不是流量配比

- 语义是"同分时的优先权重 + 冷出口的采样顺序", **不是**按权重随机分流。
- **若真需要按权重分流**: 需要比当前更强的采样纪律, 否则小权重出口永远拿不到足以判断的样本。

### C5. 看板缺出口健康视图

- 延迟归因已按「渠道 × 国家 × 出口」分组并有出口列; 但**没有**出口成功率 / 冷却状态的展示(出口指标在进程内, 未通过接口暴露)。
- **可选的改进**: 加一个只读接口暴露 `egressStates` 快照, 前端在渠道详情里显示每条出口的 EMA 与冷却剩余。

## F. 关键取舍备忘(不是待办, 但改动前必须知道)

| 事项 | 结论 | 理由 |
|---|---|---|
| certbot 认证方式 | 保持 **webroot**, 不要改回 `--nginx` | nginx 插件在自定义 vhost 上会挂起, 且每次续期重写 vhost, 会冲掉手调的缓冲与 realip 配置 |
| `X-Forwarded-For` | 必须用 `$remote_addr` **覆盖** | 用 `$proxy_add_x_forwarded_for` 会把调用方伪造的值留在前面 |
| `trusted_proxies` | 只填 `127.0.0.1` | 边缘网段会变且清单长; 归一化交给本机 nginx, 应用侧只留一个静态值 |
| 出口全部停用时 | 返回 502 配置错误, 不静默直连 | 静默直连会让管理员分不清流量到底从哪出去 |
| 中继流式响应 | 必须带 `X-Accel-Buffering: no` | 否则 nginx 攒缓冲, 流式退化成"一次性吐完" |

### 回退手册

- **恢复公网 8088**(万一有客户端还在用旧地址): 把 `/opt/switchyard/data/config.json` 的 `server.host` 改回 `0.0.0.0`, `systemctl restart switchyard`。备份在 `config.json.pre-g2-close`。
- **撤销 nginx 站点**: 删掉 `/etc/nginx/sites-enabled/switchyard-tt` 软链后 `nginx -t && systemctl reload nginx`(注意: 删了就没有 HTTPS 入口了)。
- **撤销 CF 相关配置**: `/etc/nginx/conf.d/switchyard-cf-geo.conf` 可整文件删除, 但要同时把 vhost 里的 `$trusted_cf_country` 改回 `$http_cf_ipcountry`。
