# 综合评分：失败切换与尝试预算

## 路由顺序

评分规则和现有权重不变。每一轮从当前可用候选中按评分选择；发生允许切换的错误后，本次请求排除已失败的渠道/模型组合，不重试该组合的另一把 key。剩余候选重新评分，故最终顺序可受实时健康、限流和评分变化影响，不等于成员列表固定顺序。

明确的余额不足或额度耗尽会立即暂停整个渠道（跨分组、所有模型/凭据）。暂停字段是运行时状态，不改启用开关；截止时间持久化，重启不会绕过。暂停时间复用系统硬熔断分钟数，未配置或配置为零时使用 30 分钟；到期后重新参与选路，仍余额不足则再次暂停。单个 key/model 的成功或手工清子熔断不提前解除渠道暂停。

## 渠道暂停的管理台可见性与提前恢复

渠道级暂停会外露在渠道统计里（`disabled_until`），与两件容易混淆的状态分开呈现：`enabled` 是人工启停开关，模型级/凭据级 `disabled_until` 是单项故障熔断。三者互不覆盖，界面上也分三处显示。

补足上游额度后不必干等到期：`POST /api/v1/channel/breaker/reset`，请求体 `{"id": <渠道ID>, "channel": true}`。语义刻意收窄 —— 只清渠道级暂停截止时间这一列：

- 不改 `enabled`：恢复额度不等于替人把开关打开；
- 不动凭据级与模型级熔断：那些各自代表一项尚未修好的故障，顺手清掉会把真实问题掩盖成"已恢复"；
- 可与 `key_names` / `model_names` 同时提交，条数合并到同一个 `reset` 计数；
- 未暂停或已过期时返回 `reset: 0` 且 HTTP 200，重复点击不是错误。

解除后立即重建分组成员快照，转发侧下一次选路就能用上该渠道，无需重启或等待。真实解除过一次未到期暂停会写审计 `channel.quota-resume`。

## 参数

- 总尝试次数包括首次调用。设为 **5** 表示最多尝试 5 个不同的渠道模型，不是首次加 5 次重试。
- 可用候选不足时提前结束；不为了凑次数等待失败模型冷却后再调用。可用候选仍受协议、发布/授权、渠道熔断、限流、分组成员冷却等限制。
- 评分模式不使用“同成员尝试次数”和“同成员重试间隔”；界面禁用但保留存储值，便于切换回其他模式。
- 分组整体超时仍约束所有尝试，达到超时即结束。

## 保护

错误参数和内容安全策略失败直接返回，不跨供应商绕过；已开始输出的响应不能切换拼接。图片/视频创建一旦已发出仍遵守单发语义，避免重复创建和计费。客户端取消不会被当作渠道故障。

渠道暂停只阻止新调用，不能撤回在错误到达前已经发出的并发请求。不把一般 429 限流等同于余额不足：限流仍走窗口配额控制，不熔断整个渠道。
