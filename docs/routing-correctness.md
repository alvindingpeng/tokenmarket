# 上游路由正确性修复（v1.4.3）

本轮先修评分数据与故障链，不改变价格/延迟/成功率权重，不把可靠性软折减改成硬门槛。

## 验收要求

- 流式首帧延迟与完整结果分离：收到首帧不立即认定完整成功，断流/上游错误不能被记为成功。客户端取消与客户端写入错误不得归咎上游。每轮仅一个最终成功率样本。
- 已经交付给客户端的流不重试，避免重复输出或重复执行。
- 结构化 HTTP 状态及错误体用于上游错误分类，同协议流不再丢状态而回退为未知错误。
- 熔断数据库写入成功后，固定授权与分组选路使用的缓存同步。数据库写失败不能假装熔断成功。
- 已登记的恢复探测目标不在普通候选中重复放量；亲和路径也不能绕过冷却与在途探测，冷却表读取受锁保护。
- 后台恢复必须有真实上游结果；无安全文本探测目标不算成功，媒体创建类不作为健康检查。

## 范围与后续

当前仍保留候选集 min-max 评分、现有全局 EMA 及软可靠性折减；分数尺度、跨组窗口、新鲜度、探索配额和切换滞回属于后续灰度优化，不应与本轮正确性修复混为一谈。

恢复候选的限流不等于全系统、多实例统一 half-open；渠道熔断到期放行等既有路径须按实际实现与测试说明，不宣称分布式强单飞。
