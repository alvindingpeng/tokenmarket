# 出口池（Egress）配置要求

> 适用范围：渠道编辑页「出口」步骤。本文按**实际代码约束**逐条写清，不写推测。
> 代码位置：`internal/model/egress.go`（字段与校验）、`internal/netguard/netguard.go`（地址防护）、
> `internal/relay/egress.go`（选路）、`internal/rhttp/http.go`（客户端构造）。

## 1. 它是什么

出口决定**流量从哪条线路出去**。渠道配了出口池后，转发时按实测耗时择优，某条不通自动换下一条。

⚠️ **配了出口，渠道自身的 `proxy` / `channel_proxy` 就不再生效**（`resolveUpstreamClient` 里出口优先）。
想回退到旧行为，把出口删空即可。

## 2. 字段与约束

| 字段 | 必填 | 约束 |
| --- | --- | --- |
| `name` | ✅ | 非空；**渠道内唯一**（重名报 `duplicated egress name`）。名称是增删改的定位键，改主键会让历史成绩对不上。 |
| `kind` | ✅ | 只接受 `direct` / `http` / `socks5`，其他值报 `unsupported egress kind`。 |
| `url` | `direct` 外必填 | 必须与 `kind` 的协议匹配（见下）。`direct` 填了会被清空。 |
| `region` | ❌ | 自动转大写；用于区域亲和，但 `egress_region_bonus_ms` 默认 **0 即关闭**（需要 `CF-IPCountry` 反代头，未配可信代理时恒为空）。 |
| `weight` | ❌ | 整数，**同分时的优先级**（大者先选），也是冷出口的采样顺序。**不是**按权重分流。 |
| `enabled` | ❌ | 默认 `true`。停用后不参与选路但保留配置。 |

## 3. URL 的四种合法形式

| kind | URL 写法 | 说明 |
| --- | --- | --- |
| `direct` | 留空 | 用网关本机网络出去 |
| `http` | `http://host:port` | HTTP 代理；**目标为 HTTPS 时自动用 CONNECT 建隧道** |
| `http` | `https://host:port` | 到代理这一步走 TLS |
| `socks5` | `socks5://host:port` | SOCKS5 |

三种都可内嵌凭据：`http://user:pass@host:port`（密码里的 `:` `@` `/` 需 percent-encode，如 `@` → `%40`）。

**关于 `socks5h`**：协议校验允许它，但底层 `x/net/proxy` 与 `socks5` 是同一分支，且本实现
一律把**域名**发给代理解析（`AddrDomain`）——即 DNS 始终在代理侧。写 `socks5://` 即可。

## 4. 硬性要求（会被校验拒绝的）

### 4.1 必须是公网地址（默认）

`netguard.CheckProxyURL` 在**保存时**校验，解析到私网直接拒绝：

```
egress <名>: upstream host <主机> resolves to a private address
  (refused to prevent SSRF; enable allow_private_upstream to permit internal addresses)
```

被拦的网段（`IsPrivateIP`）：

- 标准库判定：环回 `127.0.0.0/8`、`::1`、RFC1918（`10/8`、`172.16/12`、`192.168/16`）、
  链路本地 `169.254/16`、`fe80::/10`、未指定、组播；
- 额外封禁：`100.64.0.0/10`（**含阿里云元数据 100.100.100.200**）、`0.0.0.0/8`、`192.0.0.0/24`、
  `192.88.99.0/24`、`198.18.0.0/15`、`240.0.0.0/4`、`fec0::/10`、`64:ff9b::/96`。

放行办法：设置 `allow_private_upstream = true`（默认 `false`）。
⚠️ 该开关**同时放开上游和出口**的私网防护，等于重新打开 SSRF 面；且目前**没有界面入口**。

### 4.2 协议必须与 kind 一致

`kind=http` 只接受 `http://` / `https://`；`kind=socks5` 只接受 `socks5://` / `socks5h://`。
错配报 `egress <名> kind <kind> requires <协议> url, got <你填的协议>`。

### 4.3 域名解析不到时**放行**

这点常被误解：`CheckHost` 对**无法解析**的域名返回 nil（放行保存），理由是"解析不了≠确定内网"，
真正拨号时会再复核一次。所以保存成功**不代表**运行时可达。

## 5. 服务器网络可达性（保存之外的另一道门槛）

校验通过 ≠ 能连上。**保存时的私网校验拦的是地址类别，不是可达性。**

当前生产网关的网络事实（实测）：

```
接口: lo (127.0.0.1/8) + eth0 (202.6.204.216/23)   ← 无隧道、无私网网卡
路由: default via 202.6.204.1 dev eth0
```

含义：**只有能被公网路由到的地址才可能连上**。私网地址（`10.` / `172.16-31.` / `192.168.`）
会被交给公网网关后丢弃 —— 即使放开 `allow_private_upstream` 也连不上。

所以代理放在别的 VPS 上时：**那个 VPS 必须有公网 IP，且代理端口对外可达。**

## 6. 代理本身的要求（不会被校验，但会影响可用性）

1. **HTTP 代理必须支持 CONNECT**。上游几乎全是 HTTPS；只支持普通 GET 转发的「网页代理」用不了。
2. **不能有较短的 idle 超时**。98.3% 的请求是流式（SSE），TTFT p95 约 19 秒，一条流可能挂几分钟。
   代理若 60 秒无数据就掐连接，长回答会被打断。
3. **客户端连接池参数**：`MaxIdleConns=256` / `MaxIdleConnsPerHost=64` / `IdleConnTimeout=90s`
   （`clonedDefaultTransport`）。每请求建连开销目标 p95 < 150ms。
4. **到代理本身这一跳有 30 秒拨号超时**（HTTP 与 SOCKS5 一致）。

## 7. 配几条才有意义

出口池的价值是「按实测择优 + 失败自动切换」。

- **1 条**：等于固定走这条，与直接在渠道里填代理无差别；
- **2–3 条**：建议起步配置，来自不同机房/运营商；
- **全部停用**：返回 **502 配置错误**，不会静默直连（这是刻意设计，避免分不清流量从哪出去）。

选路细节：冷出口按"已观测出口的平均值"参与（既不无条件抢流量，也不会永远轮不到）；
同分时 `weight` 大的优先；失败后按 `classCooldownSeconds` 冷却，全部冷却时探最早恢复的那条。

## 8. 凭据与安全（v1.5.14 起）

- **回显掩码**：编辑页看到的是 `http://user:****@host:port`，密码不回传浏览器；
- **掩码占位识别**：只改权重/地区时不会把真实地址覆盖成掩码值；
- **错误信息剥离凭据**：`url.Parse` 失败也不会把密码带进错误信息；
- ⚠️ **库内仍是明文**：`channel_egresses.url` 未纳入信封加密（加密范围目前只有 `settings.value`
  与 `channel_keys.key/api_secret`），且会进入自动备份的 `.db` 文件。

## 9. 配好之后怎么确认生效

1. 打开该渠道的 **出口健康看板**（渠道统计弹窗内）：看每条出口的样本数、EMA 成功率、
   首响应延迟、冷却状态。**无样本的出口会标 `has_data=false`**，说明还没被选中过。
2. 「运维 → 延迟归因」按「渠道 × 国家 × 出口」分组，可看到 `egress_id` 的实际分布。
3. 若某出口一直 `has_data=false`，通常意味着它没被选中（另一条更快）而不是没生效。

## 10. 已知限制

- **出口成绩只存进程内**，重启后重新学习（每条被选中一次即有样本）；
- **不支持按权重分流**，`weight` 只是同分优先级；
- 区域亲和依赖 `CF-IPCountry`，当前入口未接入边缘（B1 未做），因此实际不可用。
