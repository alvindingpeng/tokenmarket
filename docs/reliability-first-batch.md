# 第一批运行可靠性升级

已实施并部署到生产服务 octopus-multiuser（202.6.204.216:8088）。

## 配置入口与默认值

在“限流管理”中设置并发上限，0 表示不限；实时面板显示活跃请求数。用户、API Key、渠道、凭据、渠道模型沿用现有策略解析。全部模型策略共用计数，存在单模型策略时两者同时执行。系统策略仍是各主体默认值，不是平台总额度。

在“分组 → Relay 配置”中设置：

| 参数 | 默认 | 行为 |
| --- | --- | --- |
| request_timeout_seconds | 600 | 包含等待、重试、完整流式传输；上限 3600 秒 |
| max_total_attempts | 10 | 跨所有成员的总轮次上限；上限 100 |
| max_wait_seconds | 新分组 30；旧配置缺失可为 0 | 累计排队时限；0 不等待，上限 300 秒 |
| max_waiting_requests | 0 | 每分组 FIFO 排队容量；0 关闭，上限 1000 |
| member_stream_idle_timeout_seconds | 60 | 相邻有效流事件之间最大空闲时间；上限 3600 秒 |

等待队列默认关闭。全部上游无可用容量、队列满或排队时间耗尽返回 429；请求总超时在尚未提交响应时返回 504；最大总尝试次数耗尽返回 503。已提交的流式响应无法改变 HTTP 状态，只结束流并记录失败。

## 正确性

预留票据绑定原始分钟窗口和原始 bucket；即使跨分钟或旧窗口被清理，结算不会污染新窗口。票据幂等结算，并发租约与分钟窗口独立。显式 max_completion_tokens / max_output_tokens / max_tokens 优先作为输出预算，未指定时使用既有估算上限。输入 token 仍为估算，最终按上游用量结算。

上游流式用量在末帧聚合完成后结算，并发租约保持到流结束。取消、失败、超时等退出路径释放租约。上游 429 的强制阻塞与实际 token 计数分离。手动、亲和、动态候选和空候选路径均遵守上游限流。

## 路由解释

日志详情新增“路由时间线”。relay_requests.route_events 保存接收、用户准入、选路、排队、上游准入、结束事件（每请求最多 128 条，连续重复事件合并）。relay_request_attempts.decision 保存策略、选中原因和候选排除原因。GET /api/v1/log/attempts/:id 与正文接口使用相同归属校验。展示渠道发布编码，不显示凭据明文。
