# 安全边界与凭据管理

第二批加固正在实现；部署结果以 `security-batch2-acceptance.md` 的核验记录为准。

## 管理员重新认证

高危管理操作在业务执行前验证短期二次认证凭证。控制台遇到验证要求时请求管理员重新输入当前密码，通过后继续原操作。普通列表读取使用既有登录会话。二次认证凭证绑定当前会话及账号令牌版本，密码修改、会话失效后不得复用。密码重新认证不等同于 TOTP 多因素认证或双人审批。

## 需要恢复原文的凭据

上游访问密钥以及支付、邮件、告警、会话签名等秘密配置需要在进程中恢复原文，使用信封加密存储。每次加密生成独立数据密钥，由外部主密钥包装；密文包含格式版本及认证信息，密文损坏或主密钥不匹配时拒绝读取。主密钥应独立保管，不随数据库备份一起存放。

加密数据库字段只保护静态数据副本；应用运行时仍需使用原文。主机管理员、进程内存和具有导出权限的管理员不在该加密隔离边界之内。渠道自定义请求头、代理URL或用户自行放在其他字段里的秘密不应自动认为已被覆盖，验收记录会列出实际范围。

### 外部主密钥运行契约（尚待迁移演练验收）

主密钥加载器接受 `SWITCHYARD_SECRET_KEK_FILE` 对应的文件来源或 `SWITCHYARD_SECRET_KEK` 对应的直接材料；材料为 32 字节随机值的 hex/base64 编码，不是任意口令。部署优先选择文件方式，建议放在 `/opt/switchyard/keys/master.key`，目录权限 0700、文件权限 0600，避免将秘密放入命令参数、源码或数据库。实际启动配置接线须在发布前验证，不能只凭辅助库测试认定有效。

密钥丢失会使数据库中的可恢复凭据永久无法解密。应在独立于数据库和发布备份目录的位置保存加密的恢复副本，并实际验证读取权限与恢复流程；主密钥 ID 不是密钥材料。禁止在迁移后重新生成主密钥尝试修复解密失败，也禁止把配置项改为空来回退明文读取。当前只实现单个活动主密钥的边界，不应宣称支持在线多版本轮换。

## 客户端 API Key

客户端调用凭据只需验证，不需要恢复原文，使用确定性单向哈希查询。新建凭据由服务端随机生成，明文仅在创建成功时返回一次；后续列表和更新响应只显示掩码，不能重新读取原文。旧密钥迁移后仍可用于调用，ID、归属、额度与统计关联保留。

API Key 哈希不会使用“每次生成随机 bcrypt 值再查索引”的方式；随机盐密码哈希不适合该查询流程。账号登录密码继续使用原有密码哈希机制。

## 备份与恢复

静态数据库备份需要匹配的外部主密钥才能恢复加密凭据；API Key 哈希不需要主密钥。便携 JSON 导出会按导出协议携带恢复所需凭据，必须作为秘密文件保管，其导出操作要求二次认证。已有备份加密口令与静态凭据主密钥是两套用途不同的秘密。

迁移不会自动删除历史备份里的原文。回退旧程序需要配套恢复迁移前数据库，不能直接将旧二进制运行在已哈希化、加密后的数据库上。生产部署应在停机后创建一致备份，并在重新开放写入前完成验证。
